Normalización de Bases de Datos

La normalización es un proceso sistemático para organizar datos en una base de datos relacional, eliminando redundancias y dependencias anómalas. Este proceso mejora la integridad de los datos, reduce el almacenamiento y facilita el mantenimiento.

Proceso de Normalización - Formas Normales

1FN
Primera Forma Normal

→

→
BCNF

Eliminar dependencias funcionales anómalas

Objetivos de la Normalización:
  • Eliminar redundancia: Evitar duplicación de datos
  • Prevenir anomalías: Evitar inconsistencias en actualizaciones
  • Mejorar integridad: Garantizar consistencia de datos
  • Facilitar mantenimiento: Simplificar modificaciones
  • Optimizar almacenamiento: Reducir espacio requerido

Primera Forma Normal (1FN)

Una tabla está en 1FN cuando todos los atributos contienen valores atómicos (indivisibles) y no hay grupos repetitivos. Cada celda debe contener un solo valor.

Reglas para 1FN:

  • Sin grupos repetitivos: No arrays o listas en una columna
  • Orden no significativo: El orden de las filas no debe importar
  • Clave primaria: Cada fila debe ser única

Dependencias Funcionales y Transitivas

Las dependencias funcionales y transitivas son conceptos fundamentales para entender la normalización, especialmente la Tercera Forma Normal (3FN). Comprender estos conceptos es crucial para diseñar bases de datos eficientes.

Tipos de Dependencias en Normalización

🔗 Dependencia Funcional
A
→
B

Definición: A determina B (A → B)

Significado: Para cada valor de A, existe un único valor de B

🔄 Dependencia Transitiva
A
→
B
→
C
A → C (transitiva)

Definición: A → B y B → C, entonces A → C (transitiva)

Significado: C depende de A a través de B

Ejemplos Prácticos de Dependencias

📋 Ejemplo 1: Dependencias Funcionales
Tabla: EMPLEADOS
ID_Empleado → Nombre, Departamento, Salario
Departamento → Ubicacion_Departamento

Interpretación:
• ID_Empleado determina únicamente el nombre, departamento y salario
• Departamento determina la ubicación del departamento
🔄 Ejemplo 2: Dependencias Transitivas
Tabla: ESTUDIANTES (Problema)
ID_Estudiante → Nombre, Carrera_ID, Nombre_Carrera, Facultad

Dependencias identificadas:
• ID_Estudiante → Carrera_ID (directa)
• Carrera_ID → Nombre_Carrera, Facultad (directa)
• ID_Estudiante → Nombre_Carrera, Facultad (TRANSITIVA)

Problema: Nombre_Carrera y Facultad dependen de ID_Estudiante
a través de Carrera_ID (dependencia transitiva)
✅ Ejemplo 3: Solución Normalizada
ESTUDIANTES (3FN)
ID_Estudiante → Nombre, Carrera_ID

CARRERAS (3FN)
Carrera_ID → Nombre_Carrera, Facultad

Resultado: Eliminadas las dependencias transitivas
• Cada tabla tiene dependencias funcionales directas
• No hay dependencias transitivas
Reglas para Identificar Dependencias:
  • Dependencia Funcional: Si A determina B, entonces A → B
  • Dependencia Transitiva: Si A → B y B → C, entonces A → C (transitiva)
  • Dependencia Parcial: Si solo parte de la clave determina un atributo
  • Superclave: Conjunto de atributos que determinan todos los demás

Reglas para 3FN:
  • Estar en 2FN: Prerequisito fundamental
  • Sin dependencias transitivas: Atributos no clave no dependen de otros atributos no clave
  • Dependencia directa: Todos los atributos no clave dependen directamente de la clave primaria

  • Eliminar anomalías: No debe haber dependencias funcionales problemáticas

Proceso de Normalización Completo

Escenario: Sistema de gestión universitaria - Normalización paso a paso

-- PASO 1: Tabla NO Normalizada (Problemas identificados) CREATE TABLE estudiantes_completo ( id_estudiante INT, nombre VARCHAR(100), carrera VARCHAR(100), facultad VARCHAR(100), materias VARCHAR(500), -- ❌ Múltiples valores telefonos VARCHAR(200), -- ❌ Múltiples valores profesores VARCHAR(300), -- ❌ Múltiples valores calificaciones VARCHAR(200), -- ❌ Múltiples valores creditos_totales INT, promedio DECIMAL(3,2) ); -- PASO 2: Aplicar 1FN - Eliminar grupos repetitivos CREATE TABLE estudiantes_1fn ( id_estudiante INT, nombre VARCHAR(100), carrera VARCHAR(100), facultad VARCHAR(100), materia VARCHAR(100), -- ✅ Un valor por fila telefono VARCHAR(20), -- ✅ Un valor por fila profesor VARCHAR(100), -- ✅ Un valor por fila calificacion INT, -- ✅ Un valor por fila creditos INT, promedio DECIMAL(3,2) ); -- PASO 3: Aplicar 2FN - Eliminar dependencias parciales -- Separar en tablas independientes CREATE TABLE estudiantes_2fn ( id_estudiante INT PRIMARY KEY, nombre VARCHAR(100), carrera VARCHAR(100), facultad VARCHAR(100), promedio DECIMAL(3,2) ); CREATE TABLE materias_2fn ( codigo_materia VARCHAR(10) PRIMARY KEY, nombre_materia VARCHAR(100), creditos INT ); CREATE TABLE profesores_2fn ( id_profesor INT PRIMARY KEY, nombre_profesor VARCHAR(100), departamento VARCHAR(100) ); CREATE TABLE inscripciones_2fn ( id_estudiante INT, codigo_materia VARCHAR(10), id_profesor INT, calificacion INT, telefono VARCHAR(20), PRIMARY KEY (id_estudiante, codigo_materia), FOREIGN KEY (id_estudiante) REFERENCES estudiantes_2fn(id_estudiante), FOREIGN KEY (codigo_materia) REFERENCES materias_2fn(codigo_materia), FOREIGN KEY (id_profesor) REFERENCES profesores_2fn(id_profesor) ); -- PASO 4: Aplicar 3FN - Eliminar dependencias transitivas CREATE TABLE estudiantes_3fn ( id_estudiante INT PRIMARY KEY, nombre VARCHAR(100), carrera_id INT, promedio DECIMAL(3,2), FOREIGN KEY (carrera_id) REFERENCES carreras_3fn(carrera_id) ); CREATE TABLE carreras_3fn ( carrera_id INT PRIMARY KEY, nombre_carrera VARCHAR(100), facultad VARCHAR(100) ); -- PASO 5: Verificar BCNF - Eliminar dependencias funcionales anómalas -- El diseño ya está en BCNF si no hay dependencias funcionales problemáticas

-- TABLA NO NORMALIZADA (Problemas) CREATE TABLE pedidos_no_normalizada ( pedido_id INT, fecha_pedido DATE, cliente_id INT, nombre_cliente VARCHAR(100), direccion_cliente VARCHAR(200), ciudad_cliente VARCHAR(100), producto_id INT, nombre_producto VARCHAR(100), categoria_producto VARCHAR(50), precio_unitario DECIMAL(10,2), cantidad INT, subtotal DECIMAL(10,2), total_pedido DECIMAL(10,2) );
